# Sagnac Trading website

Next.js 15 (App Router) static export, Tailwind 3, `motion` for animation. Bilingual (zh default / en) copy lives in `lib/i18n/*.ts`.

## Commands
- `npm run typecheck` — TypeScript check
- `npm run build` — static export into `out/` (needs network: next/font fetches Google Fonts)
- `npx next dev -p <port> -H 127.0.0.1` — dev server
- Production: `server.cjs` serves `out/` with `serve` on port 3003 under pm2 (`ecosystem.config.cjs`, app `sagnac-trading`); nginx site `/etc/nginx/sites-available/sagnac.ai` (copy of `nginx-sagnac.conf`) proxies sagnac.ai and sagnac.trading (+ www) to it. Cloudflare proxies both domains and terminates TLS; the origin listens on port 80 only. sagnac.ai is canonical (`metadataBase`, per-page `alternates.canonical`). The old Janus site still runs separately on port 3002. Never use `serve -s` (SPA fallback rewrites /about to /). Do not run `npm run build` in a folder whose dev server is running (it breaks the dev server's `.next`).

## Notes
- Live record (homepage section and `/performance`): one file, `data/performance/live.json`, the combined net value of the live market-making accounts (Oculus books MM2, quandora, Bybit mm), ratios only. Oculus writes it: `cd ~/JanusOculus/backend && ~/miniconda3/bin/python -m oculus.ledger.composite site --out ~/sagnac-trading/out/data/performance/live.json --out ~/sagnac-trading/public/data/performance/live.json` (crontab, daily at 00:10 UTC; log `~/JanusOculus/logs/composite-site.log`). It goes to `out/` (what is served) and to `public/` (what the next `next build` copies into `out/`), so a rebuild keeps the current record. The page fetches it at runtime; shape in `lib/performance.ts`, method in the notes of `lib/i18n/performance.ts`. Never publish an amount, an account or an exchange name.
- The homepage is one instrument (redesign of 2026-11-17). It reads as the path of the light, six chapters in `lib/chapters.ts`: source (hero), readout (`#performance`), loop (`#strategy`), observers (`#team`), origin, depart (`#contact`). `components/bench.tsx` is the ground of such a page: one `ink-surface`, the stage's canvas fixed behind it, lettering in the two margins (`components/ui/hud.tsx`). `/performance` is built on it too; `/about` is not and keeps its serif headline.
- The stage (`components/stage/`): one WebGL canvas, one fragment shader (`shader.ts`), no library. Sections never draw on it: they mark a place with `useStageAnchor(kind)` and `stage.tsx` draws its figure there, blending place and shape between the anchors near the viewport as the page scrolls. Four kinds: `word` (hero: fringes across the window, the name written in them by displacement alone, from the wordmark's own outline; two rows of letters when the band is narrow; drawn `calm`: the field at 17 % and fading towards its edges, the letters at 86 %, because full-contrast fringes the size of the window dazzle), `mark` (the logo's disc, exact proportions), `loop` (the ring: rim, six nodes, two counter-rotating pulses that meet at the node the Loop section sets in `bus.node`) and `strip` (the mark's two rows as a band). Colours are the surface's tokens, mixed by coverage (no glow), so both themes work; a theme change is picked up by itself. `bus.omega` is the rotation the page feels (scroll and pointer velocity, 0 at rest) and `bus.phase` the phase between the rows; the displaced fringes creep slowly at rest and slip with omega. Without WebGL `html[data-stage="off"]` shows still fringes on `[data-stage-figure]`. Under `prefers-reduced-motion` the stage draws but nothing drifts.
- Homepage type and furniture: `.display` (Jost, the wordmark's face, for Latin and figures; Noto Serif SC for Chinese), `.label` (small mono lettering), `.btn-beam` (a button filled by two beams from its ends), `ChapterMark`, and `ShiftText` (type cut along its middle like the mark: the halves arrive from opposite sides and lock, then the lower half slips with `bus.omega`). These classes sit in `@layer components` so utilities on the element win. Corners are square on the homepage; no rounded cards.
- Performance (`components/performance/performance-view.tsx`) is drawn the way the mark is: Fig. 1 is an interferogram (one fringe per slice of time, up to the net value above the axis in the main colour, down to the drawdown below it in the accent, the exact curve along the tips, a beam scans it in once, the reading under the pointer is printed above it), Fig. 2 the daily returns as fringes, Table 1 the latest days. SVG paint comes from the tokens (`rgb(var(--c-paper))`), never from fixed colours. The page reads the record once through `lib/use-record.ts` (hero and readout share it).
- Other Sagnac motifs kept from before: the logo's lower fringes drift by one period on load and hover (`components/logo.tsx`, `.logo-fringes`); `ScrollProgress` is two beams from the window's edges that meet in the middle at the end of the page; links underline from both ends (`.beam-link`). CSS in `app/globals.css`; every one of them rests under `prefers-reduced-motion`.
- Server and client markup must be identical whatever the reader's motion setting: always render the start state (`initial`), and under reduced motion only set the transition's duration to 0. `initial={reduce ? false : ...}` on server-rendered markup is a hydration mismatch.
- Looking at it: a hidden browser tab does not run the stage's animation; use headless Chrome over CDP and scroll in steps (scroll-driven figures need to pass through their states).
- Story page `/about`: copy in `lib/i18n/about.ts` — prologue, four dated chapters (1913 / 1925 / 1963 / 2023), the name, three convictions (observation / latency in Rust / direction from mathematics and ML), coda. Every fact in the copy is sourced; keep it that way. Glyphs in `components/about/glyphs/` are SVG line art drawn via motion `pathLength`; dashed paths must use the `fade` variant, not `draw`.
- Reduced motion on `/about`: keep server and client markup identical (hide via `motion-reduce:` CSS instead of returning null), otherwise React hydration error #418 in production.
- Visual verification: Playwright is available from the npx cache (`/home/ubuntu/.npm/_npx/e41f203b7505f1fb/node_modules/playwright`); scratch scripts and screenshots go in `.tmp/` (gitignored), e.g. `node .tmp/sagnac-shot.cjs http://127.0.0.1:3013 about zh 1440 900`.
- Brand: official logo SVGs live in `logo/` (source, with README) and are copied to `public/brand/`. `components/logo.tsx` inlines their paths (`variant` full / mark / wordmark) and fills them from the `--logo-*` CSS variables (cyan colorway, on-dark by default). `public/favicon.svg`, `favicon-32.png`, `apple-touch-icon.png` and `og.jpg` are rendered from those SVGs with `node .tmp/brand-assets.cjs`; Cloudflare caches static files for 4 h, so bump the `?v=` on their URLs in `app/layout.tsx` and the pages whenever these files change.
- Themes: only Dark (default) and Light (`lib/themes.ts`, nav toggle in `components/theme-toggle.tsx`). Both share the same root colours; every dark block carries the `ink-surface` class, and `html[data-theme="light"] .ink-surface` in `app/globals.css` flips it to light (white ground, dark text, blue accent, on-light logo). New dark blocks must get `ink-surface`, and buttons on them should hover with `hover:bg-paper/85`, not `hover:bg-white`. An inline script in `app/layout.tsx` sets `data-theme` before first paint (hence `suppressHydrationWarning` on `<html>`). The /about page uses only theme tokens, never fixed colours.
